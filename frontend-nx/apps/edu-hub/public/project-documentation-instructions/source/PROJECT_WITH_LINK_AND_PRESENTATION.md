# Projekt mit Link und Präsentation — Leitfaden / Project with link and presentation — Guide

**EduHub · opencampus.sh · Projekttyp / Project type: PROJECT_WITH_LINK_AND_PRESENTATION**

---

## Deutsch

### Zweck

Vollständiges **veröffentlichbares** Projekt: **Dokumentation**, **Präsentation**,
**Titelbild** und **externer Link** sind alle Pflicht.

### Pflichtnachweise in EduHub

| Deliverable | Pflicht |
|---|---|
| Dokumentation (Datei) | Ja |
| Präsentation (Datei) | Ja |
| Titelbild | Ja |
| Externer Link | Ja |

### Wie die Teile zusammenspielen

| Artefakt | Rolle |
|---|---|
| **Externer Link** | Live-Demo, Code, Prototyp — „das Produkt“ |
| **Präsentation** | Kompakte Story für Mentor:innen / Publikum (8–15 Folien) |
| **Dokumentation** | Vollständiger Bericht: Kontext, Technik, Team, Reflexion |
| **Titelbild** | Visueller Einstieg auf der Projektkarte |

**Tipp:** Wiederhole nicht drei Mal denselben Text. Die Doku ist der
**Tiefengang**, die Folien die **Übersicht**, der Link der **Beweis**.

### Dokumentation — Mindestinhalt

1. Executive Summary (1 Seite)
2. Team, Rollen, Zeitraum
3. Problem, Nutzer:innen, Anforderungen
4. Lösung: Architektur, Stack, Designentscheidungen
5. Link-Inhalt: Repo-Struktur, Deployment, Demo-Anleitung (Schritt für Schritt)
6. Präsentation: Ablauf des Vortrags, Kernfolien (mit Nummern)
7. Ergebnisse, Metriken oder Tests (falls vorhanden)
8. Reflexion, Risiken, nächste Schritte

### Präsentation

- Enthält **Demo-Moment** (Screenshot oder Live-Bezug zum Link)
- Klare **Takeaways** auf der letzten Folie
- Formate: PDF, PPT/PPTX, ODP — max. 22 MB

### Externer Link & Titelbild

- Siehe Leitfaden **„Projekt mit Link“** (Erreichbarkeit, HTTPS, Titelbild-Qualität)

### Checkliste vor Einreichung

- [ ] Link öffnet sich in einem Inkognito-Fenster (oder Zugang dokumentiert)
- [ ] Präsentation ohne die Doku verständlich (High-level)
- [ ] Doku ohne Live-Demo verständlich (Tiefe)
- [ ] Titelbild hochgeladen
- [ ] Alle Teammitglieder bestätigt

## English

### Purpose

Full **publishable** project: **documentation**, **presentation**, **cover
image**, and **external link** are all mandatory.

### Required deliverables in EduHub

| Deliverable | Required |
|---|---|
| Documentation (file) | Yes |
| Presentation (file) | Yes |
| Cover image | Yes |
| External link | Yes |

### How the pieces fit together

| Artifact | Role |
|---|---|
| **External link** | Live demo, code, prototype — “the product” |
| **Presentation** | Compact story for staff / audience (8–15 slides) |
| **Documentation** | Full report: context, tech, team, reflection |
| **Cover image** | Visual entry point on the project card |

**Tip:** Do not paste the same text three times. The doc is **depth**, slides
are the **overview**, the link is the **evidence**.

### Documentation — minimum content

1. Executive summary (1 page)
2. Team, roles, timeline
3. Problem, users, requirements
4. Solution: architecture, stack, design decisions
5. Linked artifact: repo layout, deployment, demo walkthrough (step by step)
6. Presentation: talk flow, key slides (with numbers)
7. Results, metrics, or tests (if any)
8. Reflection, risks, next steps

### Presentation

- Include a **demo moment** (screenshot or live reference to the link)
- Clear **takeaways** on the final slide
- Formats: PDF, PPT/PPTX, ODP — max. 22 MB

### External link & cover image

- See **“Project with link”** guide (reachability, HTTPS, image quality)

### Pre-submission checklist

- [ ] Link opens in a private/incognito window (or access is documented)
- [ ] Slides make sense without the full report (high level)
- [ ] Report makes sense without a live demo (depth)
- [ ] Cover image uploaded
- [ ] All team members confirmed
