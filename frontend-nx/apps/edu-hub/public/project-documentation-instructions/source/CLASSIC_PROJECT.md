# Klassisches Projekt — Dokumentationsleitfaden / Classic project — Documentation guide

**EduHub · opencampus.sh · Projekttyp / Project type: CLASSIC_PROJECT**

---

## Deutsch

### Zweck

Beim **klassischen Projekt** reicht als Pflichtnachweis eine **schriftliche
Dokumentation** (Upload in EduHub). Es sind **keine** Präsentation, kein
externer Link und kein Titelbild erforderlich.

### Was du in EduHub abgibst

1. **Projektteam** — bilde ein Team oder tritt einem Projekt bei (sofern dein
   Kurs das vorsieht).
2. **Titel, Slogan, Beschreibung** — in der Phase „Vorgeschlagen“ ausfüllen;
   Mentor:in oder Kursleitung bestätigt das Projekt.
3. **Dokumentation** — lade **eine Datei** hoch (siehe Formate unten).

### Empfohlener Aufbau deiner Dokumentation (ca. 3–8 Seiten)

| Abschnitt | Inhalt |
|---|---|
| **Titel & Team** | Projekttitel, Namen der Mitwirkenden |
| **Ausgangslage** | Problem, Fragestellung oder Lernziel |
| **Vorgehen** | Methoden, Schritte, verwendete Quellen/Tools |
| **Ergebnis** | Was wurde erstellt, erprobt oder erarbeitet? |
| **Reflexion** | Was hat funktioniert, was nicht, was nimmst du mit? |
| **Anhang** (optional) | Screenshots, Code-Ausschnitte, Links (als Text) |

### Qualitätskriterien

- Verständlich für Leser:innen **ohne** Vorwissen zum Thema.
- Nachvollziehbare **eigene Leistung** (nicht nur eine Linkliste).
- **Ehrliche** Reflexion — auch Teilschritte und offene Punkte sind ok.

### Technische Vorgaben (EduHub)

- **Formate:** PDF, Microsoft Word (.doc, .docx), OpenDocument Text (.odt), ZIP (.zip)
- **Max. Größe:** 23 MB pro Datei
- Abgabe unter **„Mein Projekt“ → Dokumentation**, vor Ablauf der **Abgabefrist**

### Checkliste vor Abgabe

- [ ] Titel und Beschreibung im Projekt sind aktuell
- [ ] Alle Mitwirkenden haben den Beitritt bestätigt
- [ ] Dokumentation ist vollständig und lesbar
- [ ] Datei entspricht einem erlaubten Format

## English

### Purpose

For a **classic project**, the only **mandatory** deliverable is **written
documentation** (upload in EduHub). No presentation, external link, or cover
image is required.

### What you submit in EduHub

1. **Project team** — form a team or join a project (if your course allows it).
2. **Title, tagline, description** — complete in the **Proposed** phase; staff
   confirm the project.
3. **Documentation** — upload **one file** (see formats below).

### Recommended structure (about 3–8 pages)

| Section | Content |
|---|---|
| **Title & team** | Project title, contributor names |
| **Context** | Problem, research question, or learning goal |
| **Approach** | Methods, steps, sources/tools used |
| **Outcome** | What was built, tested, or produced |
| **Reflection** | What worked, what did not, key takeaways |
| **Appendix** (optional) | Screenshots, code excerpts, links (as text) |

### Quality criteria

- Understandable for readers **without** prior knowledge of the topic.
- Clear evidence of **your own work** (not only a list of links).
- **Honest** reflection — partial progress and open points are acceptable.

### Technical requirements (EduHub)

- **Formats:** PDF, Microsoft Word (.doc, .docx), OpenDocument Text (.odt), ZIP (.zip)
- **Max. size:** 23 MB per file
- Submit under **My project → Documentation**, before the **submission deadline**

### Pre-submission checklist

- [ ] Project title and description are up to date
- [ ] All contributors have accepted their role
- [ ] Documentation is complete and readable
- [ ] File uses an allowed format
