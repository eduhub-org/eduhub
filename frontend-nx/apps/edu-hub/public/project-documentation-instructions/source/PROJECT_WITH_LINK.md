# Projekt mit Link — Dokumentationsleitfaden / Project with link — Documentation guide

**EduHub · opencampus.sh · Projekttyp / Project type: PROJECT_WITH_LINK**

---

## Deutsch

### Zweck

Dieser Projekttyp ist für **veröffentlichbare** Arbeiten gedacht: Du lieferst
**Dokumentation**, ein **Titelbild** und einen **öffentlichen Link** (z. B.
Repository, Live-Demo, Video).

### Pflichtnachweise in EduHub

| Deliverable | Pflicht | Hinweis |
|---|---|---|
| Dokumentation (Datei) | Ja | Siehe Aufbau unten |
| Titelbild | Ja | Bild für die Projektkarte |
| Externer Link | Ja | Öffentlich erreichbar, stabil |
| Präsentation | Nein | — |

### Dokumentation — empfohlener Inhalt (ca. 5–12 Seiten)

1. **Kurzfassung** (½ Seite) — Was wurde gebaut, für wen, welches Ergebnis?
2. **Team & Rollen** — Wer hat was beigetragen?
3. **Problem & Zielgruppe** — Welches Problem löst das Projekt?
4. **Lösung & Architektur** — Konzept, Technologie, wichtige Entscheidungen
5. **Umsetzung** — Meilensteine, Herausforderungen, wie der Link-Inhalt entsteht
6. **Ergebnis & Demo** — Was zeigt der **externe Link**? Wie testet man es?
7. **Reflexion & Ausblick** — Lessons learned, mögliche Weiterentwicklung

Die Dokumentation soll den Link **ergänzen**, nicht ersetzen: Leser:innen
sollen das Projekt verstehen, auch wenn der Link später nicht erreichbar ist.

### Externer Link — Anforderungen

- **HTTPS** bevorzugt; Link muss für Prüfende **ohne Login** nutzbar sein (oder
  klare Test-Zugangsdaten in der Doku).
- Typische Beispiele: Git-Repository, deployed App, Figma, Video (YouTube/Vimeo
  ungelistet ok, wenn in der Doku erklärt).
- Trage den Link in EduHub unter **„Externer Link“** ein (nicht nur in der PDF).

### Titelbild

- Querformat oder quadratisch, **mindestens** ca. 800×450 px empfohlen
- Keine urheberrechtlich geschützten fremden Bilder ohne Erlaubnis
- Repräsentiert das Projekt visuell (Screenshot, Mockup, Logo)

### Formate & Frist

- Dokumentation: PDF, Word (.doc, .docx), ODT — max. 22 MB
- Abgabe aller Pflichtfelder vor **Abgabefrist**; danach ist das Team gesperrt

## English

### Purpose

This project type is for **publishable** work: you submit **documentation**, a
**cover image**, and a **public link** (e.g. repository, live demo, video).

### Required deliverables in EduHub

| Deliverable | Required | Notes |
|---|---|---|
| Documentation (file) | Yes | See structure below |
| Cover image | Yes | Shown on the project card |
| External link | Yes | Publicly reachable, stable |
| Presentation | No | — |

### Documentation — recommended content (about 5–12 pages)

1. **Summary** (½ page) — What was built, for whom, what outcome?
2. **Team & roles** — Who contributed what?
3. **Problem & audience** — What problem does the project solve?
4. **Solution & architecture** — Concept, tech stack, key decisions
5. **Implementation** — Milestones, challenges, how the linked artifact was produced
6. **Result & demo** — What does the **external link** show? How to try it?
7. **Reflection & outlook** — Lessons learned, possible next steps

Documentation should **complement** the link, not replace it: readers should
understand the project even if the link stops working later.

### External link — requirements

- **HTTPS** preferred; link should work for reviewers **without login** (or
  provide clear test credentials in the documentation).
- Examples: Git repository, deployed app, Figma, video (unlisted YouTube/Vimeo
  is fine if explained in the doc).
- Enter the link in EduHub under **External link** (not only inside the PDF).

### Cover image

- Landscape or square, **at least** about 800×450 px recommended
- No copyrighted third-party images without permission
- Visually represents the project (screenshot, mockup, logo)

### Formats & deadline

- Documentation: PDF, Word (.doc, .docx), ODT — max. 22 MB
- Submit all required items before the **submission deadline**; the team is
  locked afterward
