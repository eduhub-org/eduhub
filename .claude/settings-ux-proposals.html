Design A notes

  • Persistent left rail = permanent table of contents; each section is a bookmarkable URL (/manage/settings/emails, etc.)
  • Email templates become a top-level nav item with expandable sub-nav: Application / Projects / Sessions / System — ready for all the new categories you described
  • Role-based access: locked nav items are greyed out with a padlock glyph; tooltip explains which role unlocks them; invisible items can be hidden entirely for lower roles
  • Scales best as settings grow — adding a new section is a single new sidebar entry
  • Trade-off: requires a layout change from the current single-column scroll to a two-column layout, and deep nesting (sidebar group → sub-item → inline edit) needs care

Design B notes

  • Overview page gives every admin an instant orientation — no scrolling needed to see all available settings
  • Each tile shows live summary data (e.g. "8 templates", "Europe/Berlin") so problems are spotted at a glance
  • Email categories become separate tiles; "soon" tiles set expectation and hold the slot before the feature ships
  • Role-based access: locked tiles use a diagonal hatching texture + padlock — clearly present but visually inaccessible; less confusing than invisible items
  • Trade-off: introduces two navigation levels (overview → detail page), which adds one click compared to today's single scroll; best mitigated by surfacing current values on the tile itself
  • Natural fit if the settings catalog continues to grow — the grid absorbs new tiles without pushing others off screen

Design C notes

  • Lowest migration cost — same URL, same layout; the current stacked sections simply gain collapsible headers
  • All groups visible at once; power users collapse what they don't need and stay in context
  • Email templates expand inline into sub-rows (Application / Projects / Sessions / System) without a page transition; clicking a row opens the full editor in a slide-over panel or inline expansion
  • Search bar at the top can be wired to highlight or filter visible rows — makes finding a specific template fast even with many items
  • Role-based access: entire groups can be hidden or rendered locked/greyed for lower-privilege roles; individual rows within a group can also carry a lock state
  • Trade-off: as email templates multiply, even the sub-rows can get long; consider pairing this with a full-page drill-down for the email template list specifically (hybrid of C + A)
